`@emdash-cms/cloudflare/auth-mail` is the site's mail broker: the one door a site's mail goes out through, in a Worker of its own (`@emdash-cms/cloudflare/auth-mail/worker`) whose Durable Object alone holds the site's send_email bindings (`EMAIL_PLUGIN`, `EMAIL_SYSTEM`) and both of its mail-budget tokens. The site's Worker reaches it through a service binding with an opaque generation capability. EmDash's own sign-in mail (magic links, sign-up verification, invites, recovery links) is four operations there: each takes a fixed request (a request carrying a subject, a body, a link, a token or a recipient is refused), rate-limits by IP and by recipient, checks eligibility, authenticates the privileged ones itself from the original credential (an `admin`-scoped API or OAuth token, or the admin's session), issues the token and renders the message with `@emdash-cms/auth`'s own code, takes the mail budget's system lane (mail-budget protocol 3, with a request id), sends through `EMAIL_SYSTEM`, and gives the place back and deletes the token when the budget or the binding refuses. Answers never carry a token, a link or an address. The header checks the provider and the broker share are in `email-headers`, and the protocol numbers in `mail-budget-protocol` and `mail-broker-protocol`. The four operations are configured by the broker alone: its Worker's env (`brokerConfigFromEnv`) and the active generation's system-lane token from its Durable Object's storage; nothing reads a budget token from an env.
