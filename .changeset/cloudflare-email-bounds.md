The Cloudflare Email Sending provider now checks every message before it reaches the binding. A `to` or `cc` that is not one plain address is refused, and a `replyTo` that is not is dropped, so form input cannot add a recipient or start a header. A `cc` is refused unless the config allows it (`allowCc`): a binding restricted to some recipients is only known to check `to`. The subject and the sender's name lose their control characters (CR and LF among them). Recipients are counted in the site's database, each count one compare-and-set row (`limits`): each sending source (auth mail, the admin's test email, each plugin) 50 an hour and 200 a day, every source together 300 a day, of which 50 are kept for auth mail (`systemReserve`) so forms and comments cannot spend the day the login email needs, and auth mail 10 a day to any one address, so requests from rotating IPs can neither flood one inbox nor spend the day. A message the binding refuses gives its places back. A send moves only its own counts and deletes none; the counts of windows that are over go in a daily cron task, at most 500 a run, and never the current window's or the one before it. With `accountBudget`, every message also takes its place in an account-wide budget, the mail-budget service reached through a service binding (`MAIL_BUDGET`) with the site's capability token (`MAIL_BUDGET_TOKEN`): only the recipients' SHA-256 hashes leave the Worker, a missing binding or token, a refusal, any error, no answer within `accountBudget.timeoutMs` (5 s) or an answer in another protocol than `MAIL_BUDGET_PROTOCOL` (1, named in every request) sends nothing, and a message the binding refuses gives its place back there too; the `status` route says whether the Worker has what it needs. `CLOUDFLARE_EMAIL_CAPABILITY` names what the provider enforces; the status route answers it, so a built Worker carries it and a deployment can check a build for it before turning its email on. Logs name a recipient's domain, never the address, and an error the binding throws has the address replaced by its domain. Without `from.name`, the sender's name is the site's title. A new "Reply-To address" setting holds the site's own address for messages that name no reply-to, and a `status` route says the sender, whether the Worker has the binding, and where replies go.
