The Cloudflare Email Sending provider now checks every message before it reaches the binding. A `to` or `cc` that is not one plain address is refused, and a `replyTo` that is not is dropped, so form input cannot add a recipient or start a header. A `cc` is refused unless the config allows it (`allowCc`): a binding restricted to some recipients is only known to check `to`. The subject and the sender's name lose their control characters (CR and LF among them). Recipients are counted in the site's database, each count one compare-and-set row (`limits`): each sending source (auth mail, the admin's test email, each plugin) 50 an hour and 200 a day, every source together 300 a day, and auth mail 10 a day to any one address, so requests from rotating IPs can neither flood one inbox nor spend the day. A message the binding refuses gives its places back. Logs name a recipient's domain, never the address, and an error the binding throws has the address replaced by its domain. Without `from.name`, the sender's name is the site's title. A new "Reply-To address" setting holds the site's own address for messages that name no reply-to, and a `status` route says the sender, whether the Worker has the binding, and where replies go.
